# ReadDuck 讀鴨

在網頁與 PDF 上做雙語對照閱讀的 Chrome 擴充功能。翻譯、解釋、摘要**全部在你自己的電腦上跑** ——
用的是 Chrome 138 起內建的裝置端 AI，不需要 API key、不產生費用、看的內容不會離開這台機器。

互動設計參考沉浸式翻譯，引擎換成 Chrome 內建的
[Translator API](https://developer.chrome.com/docs/ai/translator-api)、
[Language Detector API](https://developer.chrome.com/docs/ai/language-detection) 與
[Prompt API](https://developer.chrome.com/docs/ai/prompt-api)。

---

## 使用方法

1. 開啟 `chrome://extensions`，右上角打開「開發人員模式」
2. 點「載入未封裝項目」，選這個資料夾（零建置 —— 不必 `npm install`，不必打包）
3. 隨便開一個英文網頁，點右下角的鴨子 🦆

第一次翻譯會下載該語言對的翻譯模型，很小，通常幾秒就好。
**摘要、解釋、簡化、問答用的是另一套數 GB 的語言模型**，第一次用到時會先問過你才開始下載 ——
詳見〈[兩套模型](#兩套模型)〉。

## 功能與用法

### 1. 雙語對照翻譯網頁

譯文插在原段落下方，原文保留，兩行對著看。只翻譯視窗附近的段落，捲到哪翻到哪；
無限捲動的網站新載入進來的內容也會自動接上。

**三個入口，做同一件事：**

- 點頁面右下角的鴨子
- 在頁面上按右鍵 →「切換雙語對照翻譯」
- 點工具列的 ReadDuck 圖示 → 最上面那個開關

翻譯進行中，鴨子右下角會顯示還剩幾段沒翻完。再點一次就整頁還原，不留痕跡。

**隨手可調的三件事**（工具列圖示的小視窗裡）

| 設定 | 選項 |
|---|---|
| 翻譯成 | 39 種語言，預設繁體中文 |
| 譯文樣式 | 虛線底線（預設）／淡色底／模糊（滑過才顯示）／無樣式 |
| 在這個網站自動翻譯 | 打開後，這個網域一開頁就自動翻，不必再點 |

頁面本來就是目標語言時不會重翻一次，會直接告訴你「這個頁面已經是繁體中文」。
中英夾雜的頁面則逐段判斷，只翻外文的那幾段。

### 2. 劃選即譯 / 解釋 / 簡化

用滑鼠選取任何一段文字，旁邊會浮出一條小工具列：

- **譯** —— 翻成你的目標語言
- **解釋** —— 說明裡頭的術語與言外之意，逐字串流輸出
- **簡化** —— 改寫成更好懂的說法
- **摘要側欄** —— 把這段帶進側邊欄繼續追問

按 `Esc` 可以中止進行中的生成，結果面板上有「複製」。
在輸入框裡選字**不會**跳出工具列（免得打字時被打擾）。
不想要這條工具列的話，設定頁可以關掉 —— 右鍵選單裡一樣有「翻譯／解釋／簡化選取的文字」。

### 3. 整頁摘要與問答（側邊欄）

側邊欄會先抽出這一頁的正文（自動去掉導覽列、頁尾、側欄那些雜訊），然後：

- **產生摘要** —— 一句話結論 + 重點清單 + 名詞解釋
- **接著提問** —— 底下的輸入框直接問，模型記得整篇內容與前面幾輪對話
- 底部顯示上下文用量，滿了或想換話題就按「重設對話」

**怎麼開啟：** 滑鼠移到右下角的鴨子上 → 點展開的「摘」；或右鍵 →「開啟摘要側邊欄」；
或工具列圖示 →「摘要側欄」。

超過上下文長度的長文會自動分段閱讀再合併，不會直接失敗。
**在 ReadDuck 的 PDF 檢視器裡也能用**，讀得到的是整份文件，不只是你已經捲到的頁面。

### 4. PDF 翻譯

Chrome 內建的 PDF 檢視器沒辦法加譯文（原因見〈[運作原理](#pdf-為什麼要另外做一個檢視器)〉），
所以 ReadDuck 附了自己的檢視器。

**怎麼開啟：**

- 用 Chrome 開著 PDF 時，點右下角的鴨子 —— 會用 ReadDuck 的檢視器重開同一份檔案
- 在 PDF 網址上點工具列圖示 →「翻譯 PDF」（這時它會是主要按鈕）
- 在指向 PDF 的連結上按右鍵 →「用 ReadDuck 翻譯這個 PDF」
- 本機檔案：打開檢視器後按「開啟本機檔案」，或直接把檔案拖進去（不需要開啟「允許存取檔案網址」）

**兩種呈現方式**，工具列的按鈕隨時切換，切換不必重新翻譯：

- **左右對照**（預設）—— 左邊乾淨的原文，右邊同一頁疊上譯文。版面完全一致，可以直接對照
- **只看譯文** —— 只留疊上譯文的那一份，適合專心讀

譯文直接蓋在原文位置上，維持論文原本的版面（含雙欄），滑鼠滑過**不會**淡出；
想核對原句的話，停在譯文上會顯示原文提示。
頁面是捲到才處理的，幾百頁的文件不會一開啟就卡住。

### 5. 輸入框翻譯

在任何輸入框（`textarea`、留言框、Gmail 編輯區）打好中文，按右鍵 →
**「翻譯這個輸入框的內容」**，會就地改寫成外文。這裡用的是語言模型而不是翻譯模型，
因為要的是符合語境的自然表達而不是直譯。改壞了可以「復原」還原成原本打的字。
輸出語言在設定頁單獨設定（預設英文），跟閱讀用的目標語言分開。

## 兩套模型

ReadDuck 會用到兩套彼此獨立的模型 —— 這是 Chrome 的架構決定的，不是本專案的選擇。
官方文件的說法是「Translator 和 Language Detector API 使用專家模型，其餘所有 API 使用語言模型」：

| 功能 | 模型 | 大小 | 何時下載 |
|---|---|---|---|
| 雙語對照、劃選即譯、PDF 翻譯 | 翻譯專家模型（依語言對） | 小 | 第一次翻該語言對時 |
| 摘要、解釋、簡化、問答、輸入框改寫 | 基礎語言模型 | **數 GB** | 第一次用到這些功能時 |

所以**翻譯已經能用，不代表摘要也能馬上用**。側邊欄一開啟就會檢查語言模型在不在，
並把狀態顯示出來：已就緒、尚未下載（附「下載模型」按鈕），或這台裝置不支援（列出缺什麼）。
那是一筆很大的下載，任何情況下都會先問過你才開始；下載完成後所有 AI 功能就都能直接使用。

瀏覽器規定模型下載必須由使用者操作觸發，所以第一次一定要你自己點一下按鈕；
之後設定成自動翻譯的網站就能一開頁直接翻。

想看目前的模型狀態：工具列圖示 →「診斷」，或直接開 `chrome://on-device-internals`。

## 設定

工具列圖示 → 右上角 ⚙，或右下角鴨子滑上去點 ⚙。

- **語言** —— 閱讀的目標語言、輸入框翻譯的目標語言（兩者分開）
- **譯文外觀** —— 樣式、字級（相對原文 70–130%），改的當下就有預覽
- **行為** —— 是否顯示浮動鴨子、是否顯示劃選工具列、同時翻譯的段落數、最短翻譯長度
- **網域規則** —— 自動翻譯清單、永不翻譯清單（一行一個網域）
- **譯文快取** —— 開關、目前用量、清除。翻過的段落會存下來，重訪同一頁幾乎瞬間出現
- **其他** —— 內建 AI 診斷、回復預設值

## 系統需求

內建 AI 對硬體有實際門檻，不符合的話擴充功能會直接告訴你缺什麼：

- **Chrome 138 以上**（桌機版；行動版不支援）
- Windows 10/11、macOS 13+、Linux 或 ChromeOS 16389.0.0+
- **至少 22 GB 可用硬碟空間**（模型檔案）
- 獨立 GPU（4 GB 以上 VRAM）**或** 16 GB RAM 加 4 核心以上 CPU
- 首次下載模型時需要非計量網路連線

不確定這台機器行不行？安裝後開**診斷頁**（工具列圖示 →「診斷」），它會實測並列出結果。

## 遇到問題

| 症狀 | 原因與處理 |
|---|---|
| 頁面上沒有鴨子 | `chrome://`、擴充功能商店這類瀏覽器內部頁面不支援；或設定頁把它關掉了；剛安裝／剛重新載入擴充功能的話，已開著的分頁要重新整理一次 |
| 摘要說「讀不到這個頁面的內容」 | 同上，重新整理那個分頁即可 |
| 按了翻譯卻沒動靜 | 第一次會下載翻譯模型，開診斷頁看模型狀態 |
| 摘要／解釋要求下載數 GB | 那是語言模型，跟翻譯是兩套。看〈[兩套模型](#兩套模型)〉 |
| 說這台裝置不支援 | 開診斷頁，它會列出實際缺的是哪一項 |
| PDF 開起來說「沒有可抽取的文字」 | 掃描檔（純圖片）沒有文字層，抽不出東西；ReadDuck 不做 OCR |
| 某個網站翻譯失敗 | 該網站可能用 `Permissions-Policy` 擋掉翻譯 API，ReadDuck 會自動改走備援路徑，此時沒有串流效果 |
